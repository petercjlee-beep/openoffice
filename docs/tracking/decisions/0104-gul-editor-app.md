# 0104 훈민정음(.gul)은 새 편집기 `apps/gul`로 열고, 1단계는 문단 글 고치기와 저장까지만 한다

## 맥락

결정 0103으로 `.gul`을 읽고 고치고 저장하는 엔진이 생겼다. 고친 파일은 처음에 훈민정음이 "글자 배열/틀/페이지를 읽는 중 오류"로 거절했다. 원인은 쪽 스트림 레코드의 검사값이었다. 레코드 `id`의 낮은 바이트가 바로 앞 레코드 몸통의 바이트 합이고(첫 레코드는 스트림 머리부의 합, 마지막 레코드 뒤 1바이트는 마지막 몸통의 합), 글을 바꾸고도 옛 값을 둔 것이다. 엔진의 `refreshChecks`가 저장 때 고친 스트림의 검사값을 다시 계산하게 한 뒤, 같은 길이로 바꾼 파일·한 줄을 늘인 파일·줄인 파일이 훈민정음에서 오류 없이 열렸고, 1쪽 줄 배치는 원본과 같았다(2026-11-03, 사람이 확인하고 화면 비교).

이제 앱이 `.gul`을 열어야 한다. 새 형식 하나를 앱에 넣으려면 셸 쪽 연결 지점이 많다(탭 관리, 열기 경로와 대화상자, 최근 파일, 파일 연결, 닫기 확인, MCP 열린 문서 목록, 메뉴, 홈 화면 필터).

## 결정

- **새 편집기 `apps/gul`을 만든다.** EPUB 편집기와 같은 모양이다: 셸이 상대 경로로 가져오는 뒷단(`gul-main.ts`), preload, 렌더러. 문서는 보기마다 뒷단에 `GulDocument` 한 벌.
- **1단계의 범위는 열기, 문단 글 고치기, 저장, 다른 이름으로 저장, 닫기 확인까지다.** 화면은 쪽별 문단 목록(틀 안 글은 따로 묶음)을 텍스트 상자로 보여 준다. 글꼴·표·그림·배치는 만지지 않고, 길이가 달라진 줄은 훈민정음이 파일을 열 때 다시 짜게 둔다. AI 창, 번역, 21개 언어 도움말은 2단계로 미룬다.
- **화면은 글을 칠 때마다 뒷단에 보낸다.** 뒷단이 저장하지 않은 변경을 쥐므로 메뉴 저장과 닫기 확인이 화면의 도움 없이 끝난다(EPUB의 flush 왕복이 필요 없다).
- **열리지 않은 파일은 저장 대상이 아니다.** 암호 문서나 모르는 구조는 이유만 보여 주고 다시 쓰지 않는다.
- **`.gul` 연결은 "연결 프로그램"에만 둔다.** Windows는 `.hwp`처럼 기본 프로그램으로 잡지 않고 Explorer의 "연결 프로그램"에만 올린다(훈민정음 본 프로그램이 기본으로 남는다). 아이콘은 아직 없어 HWP 것을 쓴다.
- **화면 문구는 한국어·영어·중국어만 쓴다.** 나머지 18개 언어는 영어로 읽힌다. 저장 창·닫기 확인 문구(뒷단)는 21개 언어다. 남은 일은 `findings.md`에 있다.

## 버린 대안

- **HWP 편집기에 얹기.** `.gul`은 `.hwp`와 구조가 다르다. rhwp는 읽지 못한다.
- **텍스트·마크다운으로 바꿔 열고 저장 때 되돌려 쓰기.** 서식·표·그림이 사라진다(결정 0103에서 버린 것과 같은 이유).
- **처음부터 AI·번역·21개 언어까지.** EPUB 편집기는 파일이 약 100개다. 열기·고치기·저장이 실제로 도는지부터 확인하고 넓힌다.

## 결과

- `apps/gul`(뒷단, preload, 렌더러, 시험)과 셸 연결(경로 판별, 탭, 열기 대화상자, 최근 파일, 메뉴, 닫기 확인, 분리 창, MCP 열린 문서의 읽기·저장, 홈 화면 필터, 시작 인자, 패키징·설치 프로그램의 "연결 프로그램")이 들어갔다.
- 시험: 엔진 30개, 앱 8개(뒷단 열기·고치기·저장 왕복은 실제 문서로), 셸 시험 전체. 타입 검사와 `electron-vite build`도 통과했다.
- 아직 확인하지 못한 것: 빌드한 앱을 실제로 띄워 `.gul`을 열고 저장하는 것(Electron을 이 샌드박스에서 돌리지 못했다), 줄 수가 달라지는 긴 편집이 훈민정음에서 어떻게 보이는지, 암호 문서, 표·그림.
