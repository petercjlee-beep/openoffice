# packages/gul-engine (`@genoffice/gul-engine`)

훈민정음(삼성 한글, `.gul`) 문서를 열고, 글을 고치고, 저장하는 엔진이다. 원본 프로그램에서 온 것이 아니라 이 프로젝트가 직접 만든 패키지다. 화면 코드와 Node 전용 기능(`Buffer`, 파일 시스템)을 쓰지 않는 순수 코드라서 편집기 화면, 껍데기 앱, 터미널 명령어가 같은 코드를 쓸 수 있다. 공개된 형식 설명이 없어서, 설치된 훈민정음 2010의 `HSTORAGE.DLL`(`CHunFile::ZD_Read`, `Znextcode`)을 읽어 압축 규칙을 옮겼고, 샘플 문서 세 개로 레코드 구조를 확인했다. 암호가 걸린 문서와 2010 이전 판의 변형은 확인하지 못했다.

## 맡은 범위

- 컨테이너(`compound.ts`): OLE 복합 파일(버전 3, 512바이트 섹터)을 읽고 다시 쓴다. 디렉터리 항목(이름, 트리 연결, 클래스 ID, 시각)과 헤더는 읽은 그대로 두고, 스트림의 시작 섹터와 크기만 새로 정한다. 다른 라이브러리(`cfb`)를 쓰지 않는 이유는 아래 "항상 지켜야 하는 것"에 있다.
- 압축(`lzw.ts`): 스트림은 가변 폭 LZW다. 코드는 낮은 비트부터 채우고, 9비트에서 시작해 16비트까지 넓어진다. 256이 비우기 코드, 첫 사전 항목이 257이다. 항목을 더한 코드가 마스크(511, 1023 …)와 같아지면 다음 코드부터 한 비트 넓어진다. 사전이 가득 차면 쓰는 쪽이 비우기 코드를 내고 다시 시작한다. 읽는 쪽의 규칙을 그대로 따르므로 여기서 쓴 스트림을 원본 프로그램이 같은 규칙으로 읽는다. 원본 프로그램에는 출력에 반복 키를 XOR하는 길(`+0x84` 키, `+0x188` 길이)도 있는데, 암호 없는 문서는 키가 0 하나라서 여기서는 쓰지 않는다.
- 레코드(`records.ts`): 풀린 스트림은 `머리 + 레코드들 + 꼬리 1바이트`다. 머리는 `00 00 <종류> 11`, u32 길이, 4바이트, 그 길이만큼의 바이트이고(페이지 `00 00 00 11`, 그림틀 목록 `00 00 02 11`) 그대로 보존한다. 레코드는 `id u16 | 종류 u8 | 단계 u8 | 0x11 | 길이 u32 | 덧붙임 u32 | 몸통`이다.
- 글(`text.ts`): 종류 1 레코드 가운데 몸통이 8바이트 칸의 나열인 것이 한 줄의 글이다. 칸은 `aux u16 | 속성 u16 | 글자 u16(UTF-16) | 0 u16`이다. 속성은 `Attribute` 스트림의 글자 속성 번호이고, 줄은 0x0b(줄이 접힘) 또는 0x0a(문단 끝)로 끝난다. 28바이트 종류 1 레코드는 다음 줄의 위치·높이를 담은 설명이다. 글을 바꿀 때는 처음과 끝에서 같은 부분을 남기고 달라진 가운데만 칸을 새로 만든다. 새 글자는 바로 앞 글자의 속성을 받는다.
- 문서(`document.ts`): `GulDocument`. `PAGEn`(본문), `Anchored Frame`(표·상자 안의 글), 바탕쪽, 웹 쪽 스트림을 읽고, 문단 목록(`paragraphs`), 문단 글 바꾸기(`setParagraphText`), 찾아 바꾸기(`replaceText`), 저장(`save`)을 낸다. 문단은 줄 레코드들을 0x0a로 끝나는 데까지 묶은 것이다.

## 맡지 않는 것 (경계)

- 화면에 그리는 일, 쪽 나누기와 줄 나누기 계산은 하지 않는다. 글이 길어져도 줄을 다시 나누지 않는다(`docs/tracking/findings.md`의 "훈민정음" 항목).
- 표·그림·수식·글자 서식·문단 서식 읽기와 쓰기는 아직 없다. 그 레코드는 모르는 채로 보존한다.
- 파일을 디스크에 쓰는 일은 호출자가 한다. 여기는 저장할 바이트만 만든다.

## 항상 지켜야 하는 것

- **고치지 않은 스트림은 바이트까지 같게 둔다.** `save`는 고친 쪽(`dirty`)만 다시 압축한다. 나머지 스트림은 읽은 바이트 그대로 나간다. 아무것도 고치지 않은 저장은 모든 스트림이 원본과 같아야 한다(`tests/samples.test.ts`).
- **모르는 레코드·모르는 칸을 지우지 않는다.** 머리, 꼬리, 문서 글이 아닌 레코드, 칸의 `aux`·속성은 그대로 나간다. 글을 바꿀 때 지우는 것은 바뀐 범위 안의 보이는 글자와 줄 접힘(0x0b)뿐이다.
- **헤더의 "미니 스트림 기준 크기" 필드(오프셋 0x38)는 0x100000이다.** 원본 프로그램이 그렇게 쓴다. 스트림은 표준 4096 기준으로 놓여 있는데 필드 값 때문에 일반 라이브러리(`cfb`)는 읽기를 거절하고, 다시 쓰면 디렉터리를 자기 방식으로 재구성하고 없던 스트림(`Sh33tJ5`)까지 더한다. 그래서 `compound.ts`가 기준을 4096으로 가정해 읽고, 헤더는 읽은 그대로 쓴다. 이 필드를 "고치지" 않는다.
- **압축을 풀지 못하면 열지 않는다.** 코드가 어긋나면 `GulFormatError`("암호일 수 있음")로 거절한다. 풀리지 않은 스트림을 추측으로 다시 쓰지 않는다.
- **실제 문서는 저장소에 두지 않는다.** `tests/samples.test.ts`는 `GUL_SAMPLE_DIR`가 가리키는 폴더의 `.gul`로만 돈다. 없으면 건너뛴다.
